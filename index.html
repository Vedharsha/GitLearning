What is Git?

Git is a distributed version control system that allows developers to track changes in their codebase, collaborate with others, and manage different versions of their projects. It is widely used in software development and has become an essential tool for modern programming workflows.

Key Features of Git:

  • Distributed Architecture
  • Branching and Merging
  • Staging Area
  • Commit History

Git VS GitHub

Git is a version control system that allows developers to track changes in their codebase, collaborate with others, and manage different versions of their projects. It is a command-line tool that can be used locally on a developer's machine.

GitHub, on the other hand, is a web-based platform that provides hosting for Git repositories. It allows developers to store their code online, collaborate with others, and share their projects with the community. GitHub also provides additional features such as issue tracking, project management, and continuous integration.

Basic Git Commands

  • git init: Initializes a new Git repository in the current directory.
  • git clone: Creates a copy of an existing Git repository from a remote source.
  • git add: Stages changes to be committed to the repository.
  • git commit: Records the staged changes in the repository's history.
  • git push: Uploads local commits to a remote repository.
  • git pull: Fetches and merges changes from a remote repository into the local repository.

git init

Definition

git init creates a new Git repository in the current folder so Git can start tracking files.

What is it used for?

It is used when you are starting a new project and want to turn a normal folder into a Git repository.

When should I use it?

Use it at the beginning of a new project, before creating your first commit.

Important Note

This command does not create a remote repository. It only initializes Git locally in the current directory.

Git Bash 
user@system ~/Desktop/GitLearning (master)
$ git init

Initialized empty Git repository in /Users/system/Desktop/GitLearning/.git/

Project history

~/Desktop/GitLearning
└── index.html
    └── style.css

git status

Definition

git status shows the current state of your repository, including modified, staged, and untracked files.

What is it used for?

It helps you understand what changed since the last commit and whether files are ready to be committed.

When should I use it?

Use it often before committing, after editing files, or when you want to verify your working directory state.

Important Note

git status is a quick overview, not a detailed file diff. For detailed changes, use git diff.

$ git status

git add .

Definition

git add . stages all tracked and new changes in the current directory so they are ready to be committed.

What is it used for?

It prepares the working files to be saved in the next commit.

When should I use it?

Use this after creating or modifying files and before running git commit -m.

Important Note

The dot means “add everything from the current folder and below.” It can stage files you might not want to commit, so review your status first.

Git Bash 
user@system ~/Desktop/GitLearning (master)
$ git add .

# No output means the command succeeded.

git commit -m

Definition

git commit -m records the staged snapshot and creates a new commit with a message.

What is it used for?

It saves your changes permanently in the project history with a clear message describing what changed.

When should I use it?

git log

Definition

git log displays the commit history of the current branch in a detailed format.

What is it used for?

It helps you review what changed over time and understand the context of previous work.

When should I use it?

Use it when you want to see commit messages, authors, dates, and the history of your project.

git log --oneline --graph --all

Definition

git log --oneline --graph --all shows a compact branch-and-merge graph for all refs in the repository.

Use it when working with branches, merge conflicts, or reviewing how feature work was integrated.

git push

Definition

git push uploads local commits to a remote repository such as GitHub.

What is it used for?

It shares your latest work with others and updates the remote branch with your local commits.

When should I use it?

Use it after creating commits and when you are ready to publish or sync your branch.

Important Note

This requires a configured remote and usually authentication. If your branch has diverged from the remote, Git may ask you to pull or rebase first.

$ git push origin main

git pull

Definition

git pull fetches remote changes and merges them into your current branch.

What is it used for?

It keeps your local branch up to date with the latest changes from the remote repository.

When should I use it?

Use it before working on an existing project or when your teammates have pushed changes you need locally.

Important Note

git pull combines fetching and merging. If local changes conflict with remote changes, Git will stop and ask you to resolve them.

$ git pull origin main

git branch -d

Definition

git branch -d deletes a local branch after it has been merged.

What is it used for?

It cleans up finished work and removes branches that are no longer needed.

When should I use it?

Use it after a feature branch has been merged and is ready to be deleted.

Important Note

Git normally prevents deleting an unmerged branch. If you want to force deletion, you must use a stronger option, but that is usually not recommended.

Definition

Definition

git diff HEAD

Definition

git diff HEAD compares the current working tree and staging area against the latest commit.

What is it used for?

It shows everything changed since the last commit, including both staged and unstaged work.

When should I use it?

Use it when you want a full picture of the current branch state compared with the latest commit.

Important Note

HEAD refers to the current checked-out commit. This command is useful for seeing the total difference between your current work and the last saved checkpoint.
